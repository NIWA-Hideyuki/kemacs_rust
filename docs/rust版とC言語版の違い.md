# Rust 版と C 言語版の違い

このドキュメントは、kemacs の **Rust 版** と元の **C 言語版** を比較したものです。C 版のソースとビルド・テストは別リポジトリで管理されています。

基本方針は「できるだけ C 版の使用法に合わせる」ことです。キーバインド・起動オプション・スタートアップファイル・モードライン書式を C 版に合わせ、**どうしても合わせられない項目には理由を明記**します。

実装範囲の詳細は [`Rust移植.md`](Rust移植.md)、操作の詳細は [`kemacs使用手引書.md`](kemacs使用手引書.md) を参照してください。

---

## 1. C 版に合わせた項目

| 項目 | 変更内容 |
|---|---|
| `C-X @` (pipecmd) / `C-X #` (filter) | Rust 版に実装済みのコマンドへキーを割り当てた |
| `C-X D` (bktoshell) / `M-S` (bktoshell) / `M-C-E` (execproc) | 同じく既存コマンドへキーを割り当てた |
| `-v` / `-V` | VIEW モード (読み取り専用) にする |
| `-e` / `-E` | EDIT モード (既定) を明示 |
| `-b` | BINARY フラグを設定 |
| `-g<line>` | 起動時に指定行へ移動 |
| `-x<command>` | 起動時にコマンドを実行 |
| `-f<code>` / `-t<code>` | 文字コードを指定 (`--code` と同じ) |
| `-r` / `-R` | 制限モードのフラグを解釈 |
| `@file` | スタートアップマクロを実行 |
| `~/.kemacsrc` | 起動時に自動実行するようになった |
| モードライン `%t` / `%T` | 時刻を表示 (`HH:MM`) |
| モードライン `%<` / `%>` | 呼び出し深さに応じてその文字を繰り返す |
| `$gmodeline` / `$bmodeline` | `$mode-line-format` の別名として読み書きできる |
| query-replace の `!` | 以降の一致を確認なしで置換する |

`C-X @` などのキーは、C 版の `ebind.H_` と機械比較して欠落が見つかった5件です。コマンド本体は Rust 版にすでに実装されており、割当てだけが不足していました。

## 2. 残る違いと、合わせられない理由

### 2.1 起動時にプロンプトを伴うオプション

| オプション | C 版 | Rust 版 | 理由 |
|---|---|---|---|
| `-s<pattern>` | 起動後に検索 | 未移植 | `forwsearch` は `EditorIo::prompt()` で検索語を読むため、raw mode に入る前に実行すると端末制御が衝突する。起動後に `^S` で同じ操作ができる |
| `-k<key>` | 暗号キーを設定 | 未移植 | `setcrkey` は `prompt_secret()` でキーを読むため、同上。起動後に `M-E` または `M-x set-strong-key` で設定する |

### 2.2 query-replace の `^` (直前の置換に戻る)

C 版は置換の進行中に `^` で直前の 1 件を取り消せました。Rust 版の undo は「1 コマンド = 1 スナップショット」方式で、query-replace セッション全体が 1 つの undo エントリになります。置換 1 件だけを巻き戻す履歴を別途持つ必要があり、現在の `Buffer::Snapshot` モデルでは実現していません。

代替: `^X u` で置換セッション全体を取り消してから、やり直してください。`!` (すべて置換) と `q` (中断) は利用できます。

### 2.3 BINARY モード

`-b` と `^X M` で `MDBINARY` フラグは設定されますが、文字コード変換は停止しません。C 版は `b_code` を 0 にして変換そのものをスキップする設計でした。Rust 版は `Code` / `Eol` が型として `Buffer::load_encoded` と `encoded_text()` に組み込まれており、変換をスキップするにはこのフロー全体に分岐を追加する必要があります。

代替: 文字コードを固定したい場合は `--code` または `$bcode` を指定してください。未編集ファイルは元バイト列のまま保存されるため、実害はありません。

### 2.4 制限モード

`-r` / `-R` はフラグを解釈するだけで、コマンド実行の制限は行いません。C 版の `restricted` はファイル操作やシェル実行を弾くグローバルフラグでしたが、Rust 版には対応するチェックが各コマンドにありません。

### 2.5 対話的変数と `M-X` の補完

- 対話的変数 (`@` で始まる変数に参照時にプロンプトで入力する機能) は未移植です。`EditorIo` は `prompt()` が文字列を返すだけの単純な構成で、変数参照のたびに呼び出す仕組みを持ちません。
- `M-X` のコマンド名補完も未移植です。候補列挙と選択 UI を `EditorIo` に追加する必要があります。

### 2.6 文字コードの細部

| 項目 | C 版 | Rust 版 | 理由 |
|---|---|---|---|
| `JIS-NEW-ASCII` / `JIS-OLD-ROMAJI` | 新旧のエスケープ序列を区別 | 未移植 | iconv の "JIS" は 1 種類の変換しか提供せず、C 版が自前で持っていた新旧切替テーブルに相当するものがない |
| `$tcode` (端末コード) | ファイルコードと独立して設定 | `$bcode` の別名 | 端末側の符号化方式を別管理すると、表示と保存のコードがずれるため、Rust 版は 1 本化した |
| `MDBINARY` のコード変換無効化 | あり | フラグのみ | 2.3 節を参照 |

### 2.7 スタートアップ・キーの個別カスタマイズ

| 項目 | C 版 | Rust 版 | 理由 |
|---|---|---|---|
| `auto-mode-for-file` | 任意の正規表現でモードを追加 | 未移植 | 拡張子による組み込み判定 (`src/modes.rs::auto_mode`) のみ。パターン登録の仕組みを持たない |
| `^C` (シェル一時脱出) | raw mode を解除してシェルへ | 未移植 | `input::run()` のキー読取りループと端末状態の受け渡しが未実装。`^X !` (spawn) / `^X C` (spawncli) で代替 |
| `emacs.hlp` / `emacs.tut` | 外部ヘルプファイル | 同梱しない | `M-?` がキー割当てから組み込みでヘルプを生成するため外部ファイルが不要。チュートリアルは本ドキュメント群で代替 |

### 2.8 時刻と再帰レベルの表現

`%t` / `%<` / `%>` は実装しましたが、C 版と意味がわずかに異なります。

- `%t`: C 版は `getclock()` のローカル時刻。Rust 版は `SystemTime` から算出した **UTC** の `HH:MM` です (ローカルタイムゾーン変換は未実装)。
- `%<` / `%>`: C 版はマクロ実行の再帰レベル `relevel`。Rust 版は `Editor::prompt_depth` (プロンプトのネスト深さ) を使うため、スクリプトの呼び出し深さとは一致しないことがあります。

## 3. 誤解されやすい点 (実は共通)

以前の比較で差分として挙げられていたが、C 版の `ebind.H_` を確認した結果 **共通だった** 項目です。

| キー | C 版 | Rust 版 |
|---|---|---|
| `DEL` (0x7F) | backdel (後方削除) | backdel (後方削除) |
| `C-D` | forwdel | forwdel |
| `C-H` | backdel | backdel |
| `^X ^R` | redo | redo |
| `^R` | backsearch (逆方向検索) | backsearch |
| `M-G` | gotoline | gotoline |
| `M-N` | gotoeop (次の段落) | gotoeop |
| `M-C-N` | namebuffer (バッファ名変更) | namebuffer |

## 4. 外観の違い (Rust 版の拡張)

これらは C 版に合わせると機能が失われるため、Rust 版の拡張として残しています。

| 項目 | C 版 | Rust 版 |
|---|---|---|
| 色 | 行単位、既定は `COLOR=0` (無効) | 文字単位、8 / 256 色 (Ansi) と truecolor (RGB)。`$fcolor` / `$bcolor` で設定 |
| Markdown conceal | なし | `^X Y` または `$md-conceal=1` で強調記号とリンク URL を描画時に非表示 |
| 暗号化 | C 互換の弱暗号 (DLH-POLY-86-B) | 弱暗号に加え、`M-x set-strong-key` で XChaCha20-Poly1305 + PBKDF2 の強暗号 |
| リサイズ | `tcap.c` の SIGWINCH | crossterm の Resize イベントを 50ms ポーリングし、全行を再描画 |
| 未編集ファイルの保存 | 再エンコードされる場合があった | 元バイト列をそのまま書き戻す |
| 表現不能文字 | 素通し | `KEMACS-U+XXXX;` 形式で保存し、読み込み時に復元 |

モードラインの既定書式は両版とも同じです。

```
== %p %v (%m) == %b == File: %F == %c %-
```

## 5. 移行時のポイント

1. `make` ではなく `cargo build` / `cargo run --` を使う。
2. `~/.kemacsrc` は自動実行されるようになった。ただし対話的なコマンドはマクロ中で使わないこと。
3. 起動オプションはほぼ C 版と同じ。`-s` / `-k` だけは起動後に `^S` / `M-E` で代替。
4. BINARY モードと制限モードはフラグのみ。コード指定には `--code` を使う。
5. query-replace の `!` は使える。`^` は不可で、`^X u` でセッション全体を取り消す。
6. `%t` は UTC、`%<` / `%>` はプロンプトのネスト深さに基づく。
7. 色・conceal・強暗号は Rust 版の拡張。C 版には無い。
8. 設定・キー・仕様の詳細は [`kemacs使用手引書.md`](kemacs使用手引書.md)、[`Rust移植.md`](Rust移植.md) を参照する。
